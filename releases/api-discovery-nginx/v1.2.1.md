# api-discovery-nginx 1.2.1

Fixes for the language switcher shipped in `1.2.0` — the kind that only surface once you actually click through the interface in both languages. No behavioural, configuration, or API changes.

```
docker pull gusgh13900/api-discovery-nginx:1.2.1
```

## Why

`1.2.0` went out with six catalog-integrity tests passing. What those tests check is whether the two language files are **symmetric** — same keys, same placeholders, no empty values. That is a real guarantee, but a narrow one. A string that was never given a key at all is invisible to it. So is a substitution that wipes out part of the DOM, and so is a re-render that puts the English original back.

Switching the interface to Korean by hand, screen by screen, turned up four groups of defects the test suite could not see.

## What changed

### Help icons no longer disappear on switch

The substitution ran `el.textContent = s`. Many headings and labels carry a help icon as a child element (`<span class="help-tip">?</span>`), and writing `textContent` erased it — one switch to Korean and the icons were gone. Substitution now replaces only the element's first text node and leaves child elements intact.

### Text no longer reverts to English on re-render

Several places in `dashboard.js` wrote English strings back into `innerHTML`. The interface translated correctly, then flipped back to English the moment a table, badge, or card refreshed. Those literals now go through the catalog.

### A tab name is no longer hard-coded inside a sentence

The "upload a spec first" hint named the **Anomalies** tab in English, while the tab itself was translated — the hint pointed at a tab that was not on screen. The name is now a `{tab}` placeholder filled from the same catalog entry the tab uses, so the two can never drift apart.

### 81 strings that had no key

Six card headings in `index.html` and 75 strings in `dashboard.js` were never keyed: NGINX Plus metrics, the Try-it-out panel, flow labels, chart and model labels. They stayed English no matter what you selected.

The catalog grew from **200 to 281 keys**. Nothing was removed.

## Upgrading

No configuration changes. Pull and restart:

```bash
docker pull gusgh13900/api-discovery-nginx:1.2.1
docker pull gusgh13900/api-discovery-agent:1.2.1
```

- Your `/app/output` volume is fully compatible — database, trained models, and accounts carry over.
- The language you selected is kept; it lives in `localStorage`.
- `1.2.0` remains on Docker Hub if you need to roll back.

## On regression coverage

The test count is unchanged at 50. No automated check was added for this class of defect, and it is worth being straight about why: asserting that *rendered* text matches the selected language needs a headless browser, and that infrastructure was out of scope here.

What replaces it for now is a rule: after touching translated strings, switch the interface to both languages and look at it. A passing catalog test says the two files agree with each other — not that the interface works.

## Verified

- Full test suite: 50 passing
- Both languages walked through by hand — help icons survive the switch, tables and cards keep the selected language after re-render
- Running deployment confirmed byte-identical to source (`/static/i18n/en.json` 281 keys, `/static/dashboard.js` no diff)

## Known issue

Unchanged from `1.2.0`: the dashboard creates a default `admin` / `admin1234` account on first start. **Change the password immediately after deploying.**
